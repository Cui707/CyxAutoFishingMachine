# CyxAutoFishingMachine

**版本：`v1.0.0`**

依赖 [CrimsonCopperGrid](https://github.com/Cui707/CrimsonCopperGrid) 电网的 **Minecraft 自动钓鱼机**。

放置一台自动钓鱼机、插上钓竿、接上电网、给它一片开放水域、旁边放个箱子，
它就会按 **Minecraft 原版钓鱼机制**（真的走 `BuiltInLootTables.FISHING`）自动钓鱼，
把钓到的东西输出到箱子里，同时消耗电力和钓竿耐久。

- Minecraft `26.3` · Fabric · Java 25+
- Mod ID：`cyxautofishingmachine`
- 包名：`com.cyx.cyxautofishingmachine`
- 许可：MIT

---

## 合成表

自动钓鱼机由 **3 个铜锭 + 3 个铁锭 + 2 个红石粉 + 1 根钓鱼竿** 在工作台上合成：

|  |  |  |
| :-: | :-: | :-: |
| 🟫 铜锭 | ⬜ 铁锭 | 🟫 铜锭 |
| 🔴 红石粉 | 🎣 **钓鱼竿** | 🔴 红石粉 |
| ⬜ 铁锭 | 🟫 铜锭 | ⬜ 铁锭 |

```
游戏内配方（3×3 工作台）：

  铜锭   铁锭   铜锭
  红石   钓竿   红石
  铁锭   铜锭   铁锭
```

**材料清单**

| 材料 | 数量 | 说明 |
| --- | :---: | --- |
| 铜锭 `minecraft:copper_ingot` | 3 | 机身外壳 |
| 铁锭 `minecraft:iron_ingot` | 3 | 机械结构 |
| 红石粉 `minecraft:redstone` | 2 | 控制电路 |
| 钓鱼竿 `minecraft:fishing_rod` | 1 | 机器的「主体」，放在正中间 |

> 钓鱼竿放在配方正中央；合成出来的钓竿**不保留原钓竿的附魔与耐久**，
> 机器的钓竿需要自己再插进机器的钓竿槽里（见下文）。
>
> 若你使用的是带 `#cyxautofishingmachine:fishing_rods` 标签的模组钓竿，
> 同样可以放进机器的钓竿槽，但**合成配方只认原版钓鱼竿**。

## 安装

1. 服务端 / 客户端装好 Fabric Loader `0.19.5` 及以上；
2. 把 `fabric-api-0.161.0+26.3.jar` 放进 `mods/`；
3. 把 `crimsoncoppergrid-1.1.0.jar` 放进 `mods/`；
4. 把本模组的 `CyxAutoFishingMachine_fabric_26.3_1.jar` 放进 `mods/`；
5. 启动。

> 缺 CrimsonCopperGrid 时游戏会直接拒绝启动（`fabric.mod.json` 里声明为硬依赖），
> 这是有意的 —— 本模组的电力、界面、材质语言全部建立在上游的地基上。

## 怎么用

1. **放机器**：把自动钓鱼机放在水边，**正面朝向水面**（正面有指示灯，也是抛竿方向）。
2. **供水**：机器正面量出去要有至少一片连续水面，机器会把浮标扔到这段水面的中点。
   判定「开放水域」用的是原版规则（浮标周围 ±2 格的 5×5×4 区域），
   只有开放水域才可能钓到宝藏。
3. **插钓竿**：右键打开界面，把钓鱼竿放进左边第一个槽位。
   机器**消耗钓竿耐久**（每钓上一件东西扣 1 点），钓竿耐久耗尽会断，需要换新的。
4. **接电**：用 CrimsonCopperGrid 的导线把机器接到电源上。它是 **LOW 档**用电设备，
   最大输入 `32 FE/t`，内部缓冲 `10,000 FE`，**每杆消耗 `500 FE`**（进入等待阶段时一次性预扣）。
5. **放箱子**：在机器旁边放箱子 / 漏斗之类的容器，产物会按原版漏斗的速度（每 8 刻一件）
   自动搬进去。机器内部另有 9 格缓存当缓冲区。

机器会**自动开始下一杆**，不需要任何操作。

### 界面里能看到什么

- 实时电量条与精确数值（`电量：1234 / 10000 FE`）；
- 当前阶段：`等待鱼上钩` → `鱼正在靠近` → 收杆，以及本阶段的剩余时间；
- 水域判定：`开放` / `封闭` / `未知`（封闭水域钓不到宝藏）；
- 停机原因与解决提示，例如 `未放钓竿`「往钓竿槽里放一根钓竿」、
  `电网未连接`「用导线把机器接到电源上」。

按住 Shift 悬停物品时，物品提示里还会显示每杆耗电、当前电量还够钓几杆。

## 机制细节

### 节奏

| 阶段 | 本模组 | （原版对照） |
| --- | --- | --- |
| 等待鱼上钩 | `30 ~ 50` 刻（1.5 ~ 2.5 秒） | 100 ~ 600 刻（5 ~ 30 秒） |
| 鱼正在靠近 | `15 ~ 25` 刻（0.75 ~ 1.25 秒） | 20 ~ 80 刻（1 ~ 4 秒） |
| **一杆合计** | **2.25 ~ 3.75 秒（均值约 3 秒）** | 6 ~ 34 秒（均值约 20 秒） |

两个区间是本模组**主动调短**的，机制本身仍逐句照抄原版 `FishingHook#catchingFish`：
同样两个计时器、每刻按 `fishingSpeed` 递减、归零即切阶段、收杆那一刻掷原版战利品表。
唯一少掉的是「咬钩后留给玩家的反应窗口」—— 机器不需要反应时间，
所以咬钩即收杆，这也是它比手动钓鱼更快的原因。

### 原版行为照搬的部分

- **下雨加速**：浮标上方正在下雨时，有 25% 的几率每刻多走 1 刻；
- **遮天减速**：浮标上方看不到天空时，有 50% 的几率每刻少走 1 刻
  （这就是「在屋檐下钓鱼更慢」的来源，本模组同样保留）；
- **战利品表**：完全走原版 `BuiltInLootTables.FISHING`，
  鱼 / 垃圾 / 宝藏的权重、海之眷顾附魔的加成全部与原版一致；
- **开放水域判定**：完全走原版规则。

### 附魔

- **饵钓（Lure）**：挂上饵钓附魔的钓竿会缩短「等待鱼上钩」的时间。
  原版每级缩短 100 刻，但本模组的等待区间只剩 30~50 刻，
  照搬会把**任何等级都压到下限**、等级完全没区别。
  所以本模组按区间**等比缩放到每级 8 刻**，保住等级阶梯：

  | 饵钓等级 | 等待鱼上钩 |
  | --- | --- |
  | 无附魔 | 30 ~ 50 刻 |
  | I 级 | 22 ~ 42 刻 |
  | II 级 | 14 ~ 34 刻 |
  | III 级 | 6 ~ 26 刻 |

- **海之眷顾（Luck of the Sea）**：交给原版战利品表处理，等级越高越容易钓到宝藏。
- **耐久（Unbreaking）**：走原版 `ItemStack#hurtAndBreak`，
  「每级有 1/(等级+1) 的概率不消耗耐久」的规则自动生效。
- **修补（Mending）**：机器会把钓获产生的经验**代收**下来用于修钓竿，
  顺序与原版完全一致（先扣耐久、再修补），
  所以「耐久只剩 1 点 + 带修补的钓竿」的结果和手动钓鱼一样 —— 该断还是会断。

## 构建

```bash
# 1. 先构建前置模组（本模组的编译依赖是它的 jar）
cd ../CrimsonCopperGrid && ./gradlew build

# 2. 再构建本模组
./gradlew build
# 产物：build/libs/cyxautofishingmachine-<版本>.jar
```

前置 jar 的查找顺序（三选一即可）：

1. `libs/crimsoncoppergrid-1.1.0.jar`（仓库自带）
2. `../CrimsonCopperGrid/build/libs/crimsoncoppergrid-1.1.0.jar`
3. 运行时用 `-PccgJar=<绝对路径>` 指定

本机首次构建 / 需要重新反编译 Minecraft 源码时：

```bash
./gradlew genSources
```

跑测试：

```bash
./gradlew test              # 单元测试（钓鱼状态机、开放水域判定等纯逻辑）
./gradlew runGameTest       # 服务端 GameTest，跑完自动退出并产出 build/junit.xml
./gradlew runClientGameTest # 客户端端到端测试，自动进世界、开界面、截图后退出
```

> 本机网络需要走代理时，代理**只写在** `~/.gradle/gradle.properties`，
> 不要写进项目的 `gradle.properties`（会污染 CI）。
